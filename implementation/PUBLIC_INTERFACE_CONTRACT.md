# Public implementation interface rules

This is software boundary clarification under A1.0, not an additional source of physics.

## Value objects

Python public value objects are frozen dataclasses (or equivalent immutable validated objects). Arrays returned as borrowed views must be read-only; a mutable working array is private to one solver transaction. JSON/API objects have an explicit `schema_version`. Object and resource IDs are distinct from SHA-256 content identity. Inputs are never mutated. Errors use a stable code, component/path, message and diagnostic metadata; they never return plausible scientific values on failure.

## State and transfer types

`InventoryRate` and `TransferLedger` carry species/tracer ordering metadata, SI units and sign convention. `TransferLedger` has ID, source ID, receiver ID, time interval/stage ID and extensive increments; source/receiver copies are paired, not separately evaluated. `StepAttempt` has accepted-state-or-rejection (exclusive), proposed dt and diagnostics. A rejection cannot publish a new accepted snapshot. Exact numerical state content and stage formulas remain C1 authority; absent equations trigger SCIENTIFIC_CHANGE_REQUIRED.

## Project/application types

`EngineProject`: id, revision_hash, schema_version, component resources, display preferences. `SimulationRequest`: project revision hash, operating point/sweep definition, initial-state hash and profile identity. `SimulationRun`: id, request hash, state, ordered diagnostics, artifact manifest reference. State transitions are application-owned; submitted scientific input is immutable. `TraceSeries`: id, quantity/semantic_kind, axis values and unit, value unit, station/component ID, source_kind (SIMULATION or MEASUREMENT), parent hash. `ValidationResult`: VAL ID, fixture/reference/candidate hashes, execution status, metric/threshold pairs, qualification status, artifact links. NOT_EXECUTED/UNAVAILABLE/FAIL cannot aggregate to PASS.

## API minimum routes (S17)

JSON over local HTTP `/api/v1`. `POST /projects` returns 201 with project identity; `POST /projects/{id}/revisions` requires parent hash and returns new immutable revision (409 on mismatch). `POST /preflight` binds a revision/request and returns findings with JSON Pointer paths. `POST /runs` requires an idempotency key and accepted preflight hash; repeat same payload/key returns same run, changed payload/key fails 409. `GET /runs/{id}`, `/diagnostics`, `/results`, `/traces/{traceId}` return their typed objects; missing ID is 404, results not published returns a typed unavailable response. `POST /runs/{id}/cancel` requests cancellation; it does not pretend cancellation already occurred. `GET /compare?run_ids=...` returns parent result references and compatibility metadata, not new physical calculations. OpenAPI and TypeScript client are generated by S17; frontend consumers cannot edit them.

## Field binding contract

S17 publishes `FieldDescriptor(id, schema_pointer, domain_path, solver_input_path, dimension, display_units, required, editable, supported, provenance_key, help, domain_metadata)`. These are metadata about existing backend consumption, never instructions to invent a model. S19 binds widgets only to supported/editable descriptors. A missing scientific payload path disables the control. Field metadata and submitted SI value/hash remain in the revision manifest.

## Frontend route boundaries

S19 owns shell/navigation and a route outlet consuming named route entries. S20 owns run/preflight entry; S21 owns results/compare entry. Each entry exports route path, component and accessibility title. The shell loads registered feature entries without scientific logic. Test-only API fixtures are explicitly CONTRACT_TEST_ONLY, contain provenance/source-kind labels and cannot be saved/exported as simulation evidence. No user-facing mock engine output is provided by this foundation.

Field-group bindings and required journey assertions: `implementation/UI_FIELD_BINDINGS.md`.

## S03 runtime thermochemistry — C1.0-R3

ThermoModel uses BCR-S03-NASA-INVERSION TI-001…005 and derived identity DINO2NEXT_NASA5_CONTINUOUS 1.0.0. Energy/enthalpy inversion returns unique in-domain temperature with target and signed residual diagnostics; it does not mutate or replace conserved inputs. RAW, derived and generator hashes are separate. EOS_OUT_OF_DOMAIN and EOS_INVERSION_FAILED remain distinct; no first-root or seed-dependent success. Full signatures are in S03.

## MR-008 regional state — C1.0-R5

The S05-owned RegionalDuctState extension is delivered and accepted with S06
through exactly the three enumerated file handoffs; it does not reopen or
replace accepted homogeneous DuctState behavior. W faces and I12 inventories
are authoritative, material identities are physical input independent of
species/origins, and x is derived with explicit inverse certificates. Products
distinguish regional NASA states, conservative Q projection, compensated
inventory and pressure weighted by represented overlap DeltaW. No generic
averaged primitive vector claims homogeneous EOS meaning. Preserve weighting
and geometric residual metadata, immutable restart and recovery identity.

S06 owns regional flux/remap/stages, all physical guards and rollback, including
both FE endpoints. Unsupported regional boundary events are typed transactional
rejections. Their S07/S16 consumers require explicit creation/exhaustion,
event-time, actual-donor, paired-ledger and rollback contracts before use;
ownership is not authority to invent an unspecified numerical mechanism.
S14 evaluates sources on the represented state; S17/S18 preserve its identity;
frontend consumes backend observables without recovering physics itself.
