# Independent boundary scope assessment

Reviewer: `/root/s01_reviewer`. This evaluates ownership and claim boundaries,
not a new birth/exit algorithm.

The lack of material birth/exit handling does not invalidate the demonstrated
interior contact mechanism. A BCR can select that bounded interior mechanism
with explicit preconditions and transactional failure when a material boundary
reaches an unsupported physical endpoint. It cannot describe that selection as
a complete GEN1 engine recipe or claim functioning inflow reversal, material
insertion, exit, collision or source/event coupling.

S07 explicitly owns actual-donor boundary traces and a single shared transfer
ledger, including donor reversal without mixture averaging. S16 owns global
stage transactions, all timestep bounds, event order and rollback. These provide
appropriate consumer ownership for future integration, but ownership does not
authorize those scopes to invent an unspecified scientific birth/exit rule.
Before the affected route is implemented or accepted, an explicit contract must
define the physical data, regional inventory/geometry transfer, event timing,
paired ledger, rollback and verification requirements. Projecting to homogeneous
Q to avoid this work would violate the represented-state requirement.

Current `STATE_INTERFACE_PROPOSAL.md` explicitly says exits must be adjudicated
before the proposal is sufficient to merge S06. A narrower selection therefore
must openly distinguish BCR interior selection, implementation acceptance for
that bounded route, and later consumer acceptance. It cannot silently relabel
the existing unmet exit obligation as complete. Original fixture gates and
dependency acceptance still apply; the small contact matrix is not their PASS.

An acceptable scoped claim is interior numerical-mechanism evidence with
unsupported events rejected and recorded. Full-engine capability remains open.
This assessment approves no birth/exit recipe and waives no gate.
